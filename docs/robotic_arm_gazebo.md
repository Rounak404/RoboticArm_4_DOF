# robotic_arm_gazebo

## Overview

The `robotic_arm_gazebo` package is responsible for launching the robotic arm inside Gazebo Harmonic, spawning the robot from the URDF description, loading ros2_control, starting controllers, and providing simulation time to the ROS 2 ecosystem.

This package acts as the bridge between:

* Robot Description (`robotic_arm_desc`)
* Gazebo Harmonic
* ros2_control
* Controller Manager
* MoveIt 2

The package provides a complete simulation environment where the robotic arm can be visualized, controlled, and integrated with motion planning systems.

---

# Features

* Launches Gazebo Harmonic with a custom world
* Spawns the robot from `/robot_description`
* Loads `gz_ros2_control`
* Starts Controller Manager
* Publishes simulation time (`/clock`)
* Loads:

  * `joint_state_broadcaster`
  * `arm_controller`
  * `gripper_controller`
* Supports MoveIt 2 integration
* Supports trajectory execution through ROS 2 controllers

# URDF Modifications Required for Gazebo

The URDF generated by SolidWorks was not directly compatible with Gazebo Harmonic and required several modifications.

---

## 1. Replace Gazebo Classic ros2_control Plugin

Many ROS tutorials use Gazebo Classic plugins such as:

```xml
<hardware>
  <plugin>gazebo_ros2_control/GazeboSystem</plugin>
</hardware>
```

or

```xml
<plugin filename="libgazebo_ros2_control.so"/>
```

Since this project uses Gazebo Harmonic, these were replaced with:

```xml
<hardware>
  <plugin>gz_ros2_control/GazeboSimSystem</plugin>
</hardware>
```

and

```xml
<gazebo>
  <plugin
      filename="libgz_ros2_control-system.so"
      name="gz_ros2_control::GazeboSimROS2ControlPlugin">

      <parameters>
        path/to/controllers.yaml
      </parameters>

  </plugin>
</gazebo>
```

This change is mandatory when using Gazebo Harmonic.

---

## 2. Add ros2_control Configuration

A complete ros2_control block was added inside the URDF.

Example:

```xml
<ros2_control name="MyRobotSystem" type="system">

  <hardware>
    <plugin>gz_ros2_control/GazeboSimSystem</plugin>
  </hardware>

  <joint name="joint_1">
    <command_interface name="position"/>
    <state_interface name="position"/>
  </joint>

</ros2_control>
```

Without this block, ROS 2 controllers cannot communicate with Gazebo.

---

## 3. Add Command and State Interfaces

Each joint required explicit interfaces:

```xml
<command_interface name="position"/>
<state_interface name="position"/>
```

These interfaces allow:

* Reading joint positions
* Sending position commands
* Controller activation

---

## 4. Add Collision Geometry

The SolidWorks export mainly generated visual meshes.

Physics simulation requires collision geometry.

Example:

```xml
<collision>
  <geometry>
    <box size="0.05 0.05 0.05"/>
  </geometry>
</collision>
```

Collision models improve:

* Stability
* Physics calculations
* Collision detection

---

## 5. Add Tool Center Point (TCP)

A TCP frame was added for future manipulation tasks.

```xml
<link name="tcp_link"/>

<joint name="tcp_joint" type="fixed">
  <parent link="link_4"/>
  <child link="tcp_link"/>
  <origin xyz="0 0 0.09" rpy="0 0 0"/>
</joint>
```

The TCP frame is later used by:

* MoveIt
* Pick-and-place applications
* End-effector control

# Common Issues Encountered

## 1. Controller Activation Timeout

Error:

```text
Switch controller timed out after 5 seconds
```

Cause:

Controllers were spawned before `gz_ros2_control` completed hardware initialization.

Solution:

Delay controller spawning.

Example:

```python
TimerAction(
    period=5.0,
    actions=[
        arm_controller
    ]
)
```

---

## 2. Missing Simulation Clock

Symptoms:

```text
Didn't receive robot state with recent timestamp
```

Cause:

Gazebo simulation time was not bridged into ROS 2.

Solution:

Add clock bridge:

```python
Node(
    package='ros_gz_bridge',
    executable='parameter_bridge',
    arguments=[
        '/clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock'
    ]
)
```

Verify:

```bash
ros2 topic echo /clock
```

---

## 3. Controller Loaded but Remained Inactive

Symptoms:

```text
arm_controller [inactive]
gripper_controller [inactive]
```

Cause:

Controller Manager successfully loaded the controller but failed to claim hardware interfaces.

Verification:

```bash
ros2 control list_controllers
```

---

## 4. Hardware Interfaces Available but Unclaimed

Symptoms:

```text
joint_1/position [available] [unclaimed]
```

Cause:

Controllers failed to activate.

Check:

```bash
ros2 control list_hardware_interfaces
```

When controllers activate successfully:

```text
joint_1/position [available] [claimed]
```

---

## 5. Missing Controller YAML Configuration

Symptoms:

Controllers never appear in Controller Manager.

Cause:

The Gazebo plugin was not provided with the controller configuration file.

Required:

```xml
<parameters>
  path/to/controllers.yaml
</parameters>
```

inside:

```xml
<gazebo>
  <plugin ...>
```

---

## 6. Joint Name Mismatch

Symptoms:

Controllers fail to activate despite successful loading.

Cause:

Joint names differ between:

* URDF
* ros2_control block
* controllers.yaml

Example:

```yaml
joints:
  - joint_1
```

must exactly match:

```xml
<joint name="joint_1">
```

---

## 7. Heavy Collision Meshes

Symptoms:

* Slow simulation startup
* Poor simulation performance
* Unstable physics

Cause:

Using detailed STL meshes as collision geometry.

Recommended:

Use simplified collision shapes:

```xml
<box/>
<cylinder/>
<sphere/>
```

whenever possible.

---

## 8. Missing Gazebo Resource Path

Symptoms:

```text
Unable to find mesh
```

Cause:

Gazebo cannot locate robot meshes.

Solution:

```python
SetEnvironmentVariable(
    'GZ_SIM_RESOURCE_PATH',
    os.path.dirname(robotic_arm_desc_path)
)
```

ros2 action list

```text
/arm_controller/follow_joint_trajectory

```

---

## Inspect Action Type

```bash
ros2 action info /arm_controller/follow_joint_trajectory
```

Expected output:

```text
Action: control_msgs/action/FollowJointTrajectory
```

---

## Move Arm to Test Position

```bash
ros2 action send_goal \
/arm_controller/follow_joint_trajectory \
control_msgs/action/FollowJointTrajectory \
"{
  trajectory: {
    joint_names: ['joint_1', 'joint_2', 'joint_3', 'joint_4'],
    points: [
      {
        positions: [0.5, 0.5, -0.5, 0.5],
        time_from_start: {sec: 3}
      }
    ]
  }
}"
```

This command moves the robotic arm to a predefined pose within 3 seconds.

---

## Return Arm to Home Position

```bash
ros2 action send_goal \
/arm_controller/follow_joint_trajectory \
control_msgs/action/FollowJointTrajectory \
"{
  trajectory: {
    joint_names: ['joint_1', 'joint_2', 'joint_3', 'joint_4'],
    points: [
      {
        positions: [0.0, 0.0, 0.0, 0.0],
        time_from_start: {sec: 3}
      }
    ]
  }
}"
```

This command returns the arm to its default configuration.

---

## Open Gripper

```bash
ros2 action send_goal \
/gripper_controller/follow_joint_trajectory \
control_msgs/action/FollowJointTrajectory \
"{
  trajectory: {
    joint_names: ['joint_5', 'joint_6'],
    points: [
      {
        positions: [0.54, -0.54],
        time_from_start: {sec: 2}
      }
    ]
  }
}"
```

This command opens the gripper.

---

## Close Gripper

```bash
ros2 action send_goal \
/gripper_controller/follow_joint_trajectory \
control_msgs/action/FollowJointTrajectory \
"{
  trajectory: {
    joint_names: ['joint_5', 'joint_6'],
    points: [
      {
        positions: [0.0, 0.0],
        time_from_start: {sec: 2}
      }
    ]
  }
}"
```

This command closes the gripper.
